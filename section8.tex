\section{Conclusion}
\label{sec:conclusion}

This paper presented the first systematic literature review focused on \emph{repository
representation paradigms} (PARs) in LLM-based software engineering. Following established SLR
guidelines~\cite{kitchenham2007guidelines} and the PRISMA 2020 reporting standard~\cite{page2021prisma},
we analyzed 160 primary studies published between 2020 and 2026, deriving a seven-paradigm
taxonomy and answering five research questions.

\subsection{Summary of Key Findings}

\paragraph{RQ1 (Taxonomy).}
We identified seven repository representation paradigms: dense token embeddings (\parcmd{1}),
retrieval-augmented generation (\parcmd{2}), graph-based structural representations (\parcmd{3}),
dynamic and execution-based context (\parcmd{4}), summarization and compression (\parcmd{5}),
memory-augmented agent architectures (\parcmd{6}), and multi-step agentic frameworks (\parcmd{7}).
PAR-2 (RAG) is the most prevalent paradigm (30\% of studies), and PAR-7 (Agentic) is the
fastest-growing. Hybrid approaches combining two or more paradigms account for 38\% of studies
and are increasing in prevalence.

\paragraph{RQ2 (Task--Paradigm Mapping).}
Structured, locally constrained tasks (code completion, code search) are dominated by simpler
paradigms (\parcmd{1}, \parcmd{2}), while globally unconstrained tasks (bug localization,
program repair) attract diverse paradigm mixtures. Test generation and code translation are
significantly under-studied relative to their industrial importance.

\paragraph{RQ3 (Performance).}
Graph-augmented approaches outperform pure RAG for structured tasks by 5--15 percentage points
on representative benchmarks. Agentic frameworks achieve the best results on SWE-bench issue
resolution (up to 41\% pass@1). Dense embedding quality has plateaued, with diminishing
returns from architectural improvements since 2023.

\paragraph{RQ4 (Trade-offs).}
No paradigm dominates across all five evaluation dimensions (context coverage, retrieval
latency, training cost, scalability, benchmark availability). Interactive IDE tools should
prefer \parcmd{1} or \parcmd{2}; offline batch automation can leverage \parcmd{7}; tasks
requiring precise structural reasoning benefit from \parcmd{3}.

\paragraph{RQ5 (Open Challenges).}
We identified seven open research challenges: longitudinal benchmarks for evolving repositories,
principled hybrid paradigm design, energy-aware evaluation, multilingual/multi-stack support,
adversarial robustness, human-AI collaborative representation, and formal verification
integration.

\subsection{Implications for Research and Practice}

For \textbf{researchers}, this survey highlights several high-value research directions. The
most immediate opportunity is developing principled frameworks for hybrid paradigm design,
as the ad hoc hybridization currently prevalent in the literature is unlikely to be optimal.
Longitudinal benchmarks that capture the dynamics of repository evolution would enable more
realistic evaluation of all paradigms. Energy measurement should become a standard evaluation
dimension alongside performance metrics.

For \textbf{practitioners}, this survey provides actionable guidance for paradigm selection.
The choice of paradigm should be driven primarily by latency requirements and task
characteristics: for interactive IDE completion, \parcmd{2} with a fast retriever is the
right choice; for nightly batch issue triage, \parcmd{7} with an agentic framework is more
appropriate; for impact analysis and refactoring support, \parcmd{3} with a dependency graph
backend provides the richest structural context.

\subsection{Replication and Open Science}

In the interest of open science, we have made the following artefacts publicly available
in the replication package: the full search protocol, all screening decisions with rationales,
the complete data extraction spreadsheet (160 rows $\times$ 10 fields), the NVivo project
file with all coding decisions, and the analysis code used to generate the figures and tables
in this paper. We invite the community to extend this corpus as new studies are published.

\subsection{Final Remarks}

The question of how LLM-based agents represent code repositories is not merely a technical
detail: it is the foundational question that determines the capabilities and limitations of
the entire class of LLM-based software engineering systems. As context windows grow larger,
as model capabilities improve, and as repositories become richer and more complex, the
representational challenge will evolve rather than disappear. We hope that this systematic
review provides a solid intellectual foundation for the next generation of research in this
rapidly evolving and critically important area.
