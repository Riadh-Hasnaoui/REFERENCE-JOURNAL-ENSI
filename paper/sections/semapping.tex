\section{Bidirectional Task--Paradigm Mapping}
\label{sec:semapping}

Having established the PAR taxonomy in Section~\ref{sec:taxonomy}, we now examine how these
paradigms map onto the software engineering tasks most commonly addressed in the literature.
We first define the seven canonical SE tasks (Section~\ref{subsec:tasks}), then present the
task-to-paradigm mapping (Section~\ref{subsec:task2par}), and finally the paradigm-to-task
mapping (Section~\ref{subsec:par2task}).

\subsection{Canonical SE Tasks}
\label{subsec:tasks}

From our data extraction, we identified seven software engineering tasks that collectively
account for over 95\% of the task targets in the 160 primary studies:

\begin{description}[leftmargin=2.5em, labelwidth=2.5em]

\item[\textbf{T1:}] \textit{Code Completion.} Given an incomplete code fragment within a
  repository context, generate the most probable continuation. This is the highest-frequency
  task in the corpus (78 studies), reflecting its direct industrial applicability in IDE
  integration tools. The task ranges from simple next-token prediction to multi-line function
  body generation. Key benchmarks include RepoBench~\cite{liu2024repobench},
  CrossCodeEval~\cite{ding2023crosscodeeval}, and M2RC-EVAL~\cite{liu2025m2rceval}.

\item[\textbf{T2:}] \textit{Bug Localization and Fault Localization.} Given a bug report,
  failing test case, or anomalous runtime observation, identify the file(s) and/or function(s)
  responsible for the observed failure. This task requires synthesizing multiple types of
  repository information: source code structure, commit history, test coverage data, and
  natural language issue descriptions. Key benchmarks include SWE-bench~\cite{jimenez2024swebench}
  (file-level localization), BugsCpp, and Defects4J.

\item[\textbf{T3:}] \textit{Code Generation (Feature Implementation).} Given a natural language
  description of a feature or requirement, generate the implementation as one or more new
  functions, classes, or modules, correctly integrated with the existing repository. This is
  more open-ended than T1 since the location and structure of the output is not predetermined.
  Key benchmarks include DevEval~\cite{li2024deveval}, FEA-Bench~\cite{li2025feabench},
  and ProjectEval~\cite{liu2025projecteval}.

\item[\textbf{T4:}] \textit{Code Translation.} Given a repository or component in a source
  programming language, translate it to a target language while preserving semantics. This
  task requires understanding not just individual functions but the inter-module dependency
  structure that must be reproduced in the target language. Key benchmarks include
  RustRepoTrans~\cite{ou2025rustrepo}, ClassEval-T~\cite{xue2025classevalt}, and
  RepoTransBench~\cite{wang2026repotransbench}.

\item[\textbf{T5:}] \textit{Test Generation.} Given a code unit (function, class, or module)
  within its repository context, generate test cases that achieve high code coverage and
  expose potential defects. Repository context is critical for generating tests that correctly
  mock dependencies and satisfy preconditions. Key benchmarks include the datasets from
  CoverUp~\cite{altmayer2025coverup}, ChatUniTest~\cite{chen2024chatunittest}, and
  LSPRAG~\cite{go2025lsprag}.

\item[\textbf{T6:}] \textit{Program Repair (Automated Bug Fixing).} Given a buggy repository
  and a localization signal (e.g., a failing test or a bug report), generate a patch that
  fixes the bug while not breaking existing tests. Program repair differs from feature
  implementation in that it must preserve existing behavior and is constrained by the
  patch's local scope. Key benchmarks include SWE-bench~\cite{jimenez2024swebench},
  Multi-SWE-bench~\cite{zan2025multiswebench}, and Defects4J.

\item[\textbf{T7:}] \textit{Code Search and Retrieval.} Given a natural language query
  describing a code functionality, identify the most relevant code fragments in the repository.
  While this is sometimes treated as an infrastructure task rather than an SE task in its own
  right, we include it because it directly determines the quality of context available for all
  other tasks and is the primary evaluation target for \parcmd{1} systems.

\end{description}

Several patterns emerge from this table. First, \textbf{T1 (Code Completion) is dominated by
\parcmd{2} (RAG)} with 28 studies, followed by \parcmd{3} (graphs) with 16. This reflects
both the task's high practical relevance and the relative ease of evaluating completion
quality with token-overlap metrics such as Exact Match and Edit Similarity.

Second, \textbf{T2 (Bug Localization) and T6 (Program Repair) show the most diverse paradigm
distributions}, with roughly equal representation across \parcmd{3}, \parcmd{4}, and \parcmd{7}.
This suggests that these tasks genuinely benefit from multiple representational strategies
and that no single paradigm has established dominance.

Third, \textbf{T7 (Code Search) is almost exclusively addressed by \parcmd{1}} (embedding-based
approaches), with only one study using \parcmd{2}. This reflects the historical development of
the field, where code search was the primary application for learned code embeddings before
the LLM era, and has not yet fully transitioned to more holistic paradigms.

Fourth, \textbf{T4 (Code Translation) and T5 (Test Generation) are the least-studied tasks},
with 11 studies each. This represents a significant opportunity for future research, as both
tasks are industrially important and their repository-level requirements are substantially
different from the more-studied tasks.

\label{subsec:par2task}

An important observation from the paradigm-to-task mapping is that \parcmd{7} (Agentic) is
the only paradigm applied to all seven tasks, reflecting its generality. However, this
generality comes at a significant cost in inference time and engineering complexity.
Practitioners should reserve \parcmd{7} for tasks that genuinely require adaptive exploration;
for well-structured tasks with clear locality patterns (e.g., function-level code completion),
simpler paradigms such as \parcmd{2} or \parcmd{1} will be more cost-effective.

\subsection{Coverage Gaps and Under-Served Task--Paradigm Combinations}

Examining the cells of Table~\ref{tab:task2par}, we identify several noteworthy \emph{gaps}:
cells where the task--paradigm combination appears theoretically promising but has received
little research attention.

\paragraph{Test Generation with Graph-Based Representations.}
Only one study applies \parcmd{3} to T5 (Test Generation). Yet dependency graphs are
theoretically well-suited to test generation: they provide precise information about which
external dependencies need to be mocked, which side effects need to be anticipated, and which
code paths are exercised by different inputs. This gap likely reflects the historical
disconnection between the program analysis community (which produces graph-based tools) and
the LLM-based test generation community.

\paragraph{Code Translation with Memory-Augmented Architectures.}
Only one study applies \parcmd{6} to T4 (Code Translation). Repository-level code translation
is inherently a stateful process: the translator must maintain a consistent mapping from source
to target language constructs as it processes different files. A memory-augmented approach that
accumulates this mapping as it translates seems well-motivated but has not yet been explored.

\paragraph{Code Search with Agentic Frameworks.}
No studies apply \parcmd{7} to T7 (Code Search). This is somewhat expected since code search
is typically expected to return results within milliseconds, making multi-step agentic search
impractical. However, there may be a role for lightweight agentic strategies in disambiguating
ambiguous queries through clarifying sub-queries, a direction not yet explored.

\subsection{Temporal Evolution of Paradigm Adoption}

Figure~\ref{fig:paradigm-evolution} shows how the fraction of primary studies using each
paradigm has changed over the 2020--2026 period. The data reveals a clear temporal succession:
\parcmd{1} (embeddings) dominated in 2020--2021, was largely supplanted by \parcmd{2} (RAG)
in 2022--2023, and has been increasingly complemented by \parcmd{3} (graphs) and \parcmd{7}
(agentic) from 2024 onward.
