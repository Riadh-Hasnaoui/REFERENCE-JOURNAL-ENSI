\section{Synthesis Findings}
\label{sec:findings}

\subsection{Paradigm Dominance Trends (2020--2026)}
\label{subsec:trends}

The temporal distribution of primary studies across paradigms reveals
three clear transitions:

\begin{enumerate}
  \item \textbf{2020--2022 — Embedding era.}
        PAR-1 (dense embeddings) and early PAR-2 (text retrieval) dominate the
        early corpus, anchored by CodeBERT~\cite{feng2020codebert},
        GraphCodeBERT~\cite{guo2021graphcodebert}, UniXcoder
        \cite{guo2022unixcoder}, and ReACC~\cite{lu2022reacc}.

  \item \textbf{2023--2024 — RAG and graph explosion.}
        PAR-2 becomes the dominant paradigm as RAG infrastructure matures
        (RepoCoder~\cite{zhang2023repocoder}, CoCoMIC~\cite{ding2024cocomic},
        Repoformer~\cite{wu2024repoformer}).
        PAR-3 (graph-based) grows rapidly as code graph databases become
        available (GraphCoder~\cite{liu2024graphcoder}).
        PAR-7 emerges at scale with SWE-agent~\cite{yang2024sweagent} and
        AutoCodeRover~\cite{zhang2024autocoderover}.

  \item \textbf{2025--2026 — Agentic dominance.}
        PAR-7 surpasses PAR-2 in raw study count and in benchmark performance
        on SWE-bench~\cite{jimenez2024swebench,zhang2025swebenchlive}.
        PAR-5 (memory) and hybrid PAR-2+PAR-7 pipelines emerge as active
        research threads.
\end{enumerate}

\subsection{Benchmark Validity Threats}
\label{subsec:benchthreats}

A critical cross-cutting finding of the synthesis is the \emph{static
repository bias}: benchmarks that fix a repository version at collection time
and evaluate models against that static snapshot systematically overestimate
real-world performance.

Zheng et al.~\cite{zheng2025humanevo} demonstrate this quantitatively through
HumanEvo, an evolution-aware benchmark that pairs each evaluation instance with
the repository state at the time of the corresponding developer commit.
Their results show a 10--61\% performance degradation when models are evaluated
against the correct temporal repository state rather than a static snapshot.

The three paradigms most affected by this bias are precisely those with
\emph{stale} context freshness (D6): PAR-1 (offline embeddings), PAR-3
(offline graphs), and PAR-6 (offline summaries).
PAR-4 and PAR-7 are immune, as they construct context from the live repository
state.
This finding has direct implications for benchmark design: studies evaluating
PAR-1, PAR-3, or PAR-6 systems on static-snapshot benchmarks should report
a degradation estimate when applicable.

\subsection{Open Challenges}
\label{subsec:challenges}

The synthesis reveals 11 open research challenges:

\begin{enumerate}
  \item \textbf{Temporal freshness.}
        Bridging the gap between offline representation quality (PAR-1, PAR-3,
        PAR-6) and real-time freshness (PAR-4, PAR-7) remains unsolved.
        Incremental graph updates and continuous embedding re-indexing are
        partial solutions.

  \item \textbf{Token budget optimisation.}
        PAR-7 systems accumulate very high token costs ($O(i \cdot a)$).
        SWE-Pruner~\cite{wang2026swepruner} begins to address this, but no
        principled framework exists for dynamic budget allocation across
        paradigms.

  \item \textbf{Cross-paradigm hybridisation.}
        Several high-performing systems combine paradigms (e.g., PAR-2 + PAR-3
        in CodexGraph~\cite{liu2025codexgraph}, PAR-5 + PAR-7 in
        LingmaAgent~\cite{ma2025lingmaagent}).
        A principled framework for paradigm composition is lacking.

  \item \textbf{Multilingual repositories.}
        Most primary studies evaluate on Python or Java.
        Repository representation for polyglot repositories (mixing
        Python, C++, TypeScript, Rust) is largely unaddressed.

  \item \textbf{Very large repositories.}
        Industrial repositories with $10^5$+ files expose scalability limits of
        PAR-3 (graph construction) and PAR-7 (exploration cost).

  \item \textbf{Evaluation methodology standardisation.}
        The field lacks a shared evaluation protocol; results across studies
        are often incomparable due to different benchmarks, metrics, and
        repository snapshots.

  \item \textbf{Privacy-preserving repository representation.}
        Sending proprietary code to commercial LLM APIs is a barrier to
        industrial adoption.
        Local representation techniques (PAR-5, PAR-6 with local LLMs) are
        under-researched.

  \item \textbf{Multi-modal repository artifacts.}
        Repositories contain not only code but also issues, pull requests,
        documentation, and CI logs.
        PAR-2 and PAR-7 studies begin to exploit these modalities, but no
        paradigm treats them as first-class representation inputs.

  \item \textbf{Context freshness for deployed systems.}
        In production, the repository evolves continuously.
        Maintaining accurate representations without full re-indexing is an
        open engineering and research challenge.

  \item \textbf{Benchmark temporal validity.}
        As demonstrated by HumanEvo~\cite{zheng2025humanevo}, existing
        benchmarks suffer from temporal contamination.
        New benchmarks with built-in temporal controls are needed.

  \item \textbf{Theoretical foundations.}
        The RRP as defined in Section~\ref{subsec:rrp} invites a formal
        analysis: what is the information-theoretic limit of context quality
        under a token budget $\tau$?
        No theoretical work on this question exists.
\end{enumerate}
