\section{Related Work}\label{sec:relatedwork}

Several surveys have examined LLM applications in software engineering at
various levels of granularity.  Hou~et~al.~\cite{hou2024llmse_slr} provide the
broadest coverage, mapping LLM techniques to SE tasks, but do not distinguish
between file-level and repository-level representation.
Husein~et~al.~\cite{husein2025llmcompletion_slr} focus specifically on code
completion, and Jiang~et~al.~\cite{jiang2026surveycodegen} survey code
generation more broadly.  Tao~et~al.~\cite{tao2026ragsurvey} survey
retrieval-augmented code generation with a focus on repository-level
approaches.  Zhang~et~al.~\cite{zhang2026surveyse} provide a comprehensive
survey of LLMs for software engineering.

Crucially, none of these surveys: (i)~define a formal taxonomy of
\emph{repository representation paradigms}; (ii)~assess technology readiness
levels across paradigms and tasks; or (iii)~systematically quantify evaluation
biases such as the stale-context threat characterised in
Section~\ref{sec:gaps}.  Our SLR fills these gaps.
