\section{Introduction}
\label{sec:intro}

%% ----------------------------------------------------------
%% 1.1  The New Paradigm: LLMs as the Engine of Automated SE
%% ----------------------------------------------------------
The last decade has witnessed a fundamental transformation in
software engineering (SE): the emergence of Large Language Models
(LLMs) as universal reasoning engines for code-related tasks.
From generating entire functions from natural-language specifications
to autonomously resolving complex GitHub issues, LLMs now underpin
a rapidly expanding ecosystem of automated SE tools
\cite{hou2024llmse_slr,jiang2026surveycodegen,zhang2026surveyse}.
Systematic analyses reveal that this technological shift is not
incremental---it represents a qualitative leap in the scope and
automation depth achievable across the full SE lifecycle, spanning
code completion \cite{husein2025llmcompletion_slr},
code generation \cite{jiang2026surveycodegen},
bug fixing \cite{zhang2025patch,bouzenia2025repairagent},
refactoring \cite{oueslati2026refagent,wang2025divideconquer},
test generation
\cite{altmayer2025coverup,chen2024chatunitest,zhang2025citywalk},
and code review \cite{olewicki2026reviewassist}.

%% ----------------------------------------------------------
%% 1.2  The Repository Gap: From Snippets to Real-World Codebases
%% ----------------------------------------------------------
Despite this remarkable progress, a critical structural mismatch
has emerged between the granularity at which LLMs naturally
operate and the granularity at which real-world software exists.
LLMs are pre-trained on isolated code snippets and single-function
inputs, yet industrial software systems are vast, interconnected
\emph{repositories} composed of hundreds of interdependent files,
multiple programming languages, complex dependency graphs, and
evolving issue histories
\cite{bairi2024codeplan,le2026notnatural,luo2026rpg}.
This ``repository gap'' manifests concretely: a completion model
that is unaware of cross-file imports produces incorrect API calls
\cite{ding2024cocomic,zhang2023repocoder};
a bug-fixing agent that ignores project-level call chains
localizes faults in the wrong module
\cite{chen2025locagent,jiang2025issuelocgraph};
and a refactoring system that lacks a global architectural view
introduces regression defects across the codebase
\cite{bairi2024codeplan,wang2025divideconquer}.
Recent empirical benchmarks have quantified this gap rigorously:
SWE-bench \cite{jimenez2024swebench}, CrossCodeEval
\cite{ding2023crosscodeeval}, RepoBench \cite{liu2024repobench},
and DevEval \cite{li2024deveval} all demonstrate that repository-aware
approaches substantially outperform their single-file counterparts
on real-world tasks.

%% ----------------------------------------------------------
%% 1.3  A Proliferation of Approaches Without Unified Taxonomy
%% ----------------------------------------------------------
In response to this challenge, the research community has proposed
a rich and rapidly growing set of \emph{repository representation
strategies}---techniques designed to extract, structure, and inject
relevant repository-level context into LLM prompts or fine-tuning
pipelines.
These strategies range from dense neural embeddings
(CodeBERT \cite{feng2020codebert},
GraphCodeBERT \cite{guo2021graphcodebert},
UniXcoder \cite{guo2022unixcoder})
and retrieval-augmented generation (RAG) pipelines
(RepoCoder \cite{zhang2023repocoder},
ReACC \cite{lu2022reacc},
CodeRAG \cite{zhang2025coderag})
to graph-based structural encodings
(CodexGraph \cite{liu2025codexgraph},
RepoGraph \cite{ouyang2025repograph},
GraphCoder \cite{liu2024graphcoder}),
execution-guided dynamic representations
(IRCoCo \cite{li2024irCoCo},
RAP-Gen \cite{wang2023rapgen}),
memory-augmented agent contexts
(CodeMEM \cite{wang2026codemem},
LingmaAgent \cite{ma2025lingmaagent}),
context compression and summarization
(LongCodeZip \cite{shi2025longcodezip},
SWE-Pruner \cite{wang2026swepruner},
CodeS \cite{zan2025codes}),
and full agentic iterative exploration frameworks
(SWE-Agent \cite{yang2024sweagent},
AutoCodeRover \cite{zhang2024autocodeRover},
RepairAgent \cite{bouzenia2025repairagent},
MetaGPT \cite{hong2023metagpt}).
The sheer variety of these approaches---each motivated by a
different downstream task, operating at a different level of
code abstraction, and evaluated on different benchmarks---makes it
extremely difficult for practitioners and researchers to orient
themselves in this space, select the most appropriate strategy
for a given SE objective, or identify open research challenges.

%% ----------------------------------------------------------
%% 1.4  Limitations of Existing Surveys
%% ----------------------------------------------------------
Several surveys and systematic reviews have partially addressed
this space.
Hou~et~al.~\cite{hou2024llmse_slr} provide a broad and
comprehensive SLR of LLMs for software engineering across 395
primary studies, but their coverage is deliberately general and
does not propose a fine-grained taxonomy of \emph{repository
representation mechanisms}.
Husein~et~al.~\cite{husein2025llmcompletion_slr} focus specifically
on code completion, providing important insights on RAG and
fine-tuning strategies but scoping their review to a single SE
task and therefore missing cross-task comparative analysis.
Jiang~et~al.~\cite{jiang2026surveycodegen} survey LLMs for code
generation, covering prompt engineering and fine-tuning approaches
at length, yet do not systematically classify the structural
encoding strategies used to represent multi-file repositories.
Tao~et~al.~\cite{tao2026ragsurvey} provide a focused survey of
retrieval-augmented code generation with a repository-level lens,
but their scope is limited to RAG-based paradigms and leaves
graph-based, memory-augmented, and agentic representations
largely uncovered.
Zhang~et~al.~\cite{zhang2026surveyse} offer a broad perspective on
LLMs for SE from an industrial standpoint, without drilling down
into the specific mechanisms that bridge repository structure and
LLM context.

In summary, \emph{no existing work provides a unified, task-aware
taxonomy that systematically classifies the full spectrum of
repository representation paradigms and links each paradigm to its
downstream SE objectives, evaluation benchmarks, and empirical
performance characteristics.} This gap is the primary motivation
for the present study.

%% ----------------------------------------------------------
%% 1.5  Contributions
%% ----------------------------------------------------------
This paper addresses the gap above through a Systematic Literature
Review (SLR) conducted following the Kitchenham~\&~Charters
methodology \cite{kitchenham2007guidelines} and reported
in accordance with the PRISMA 2020 guidelines \cite{prisma2020}.
Our primary contributions are:

\begin{enumerate}

  \item \textbf{A Seven-Paradigm Taxonomy of Repository Representation.}
  We define and rigorously characterize seven orthogonal paradigms
  for representing code repositories in LLM-based SE:
  (i)~Repository-Level Code Embedding \& Dense Representation (PAR-1),
  (ii)~Retrieval-Augmented Cross-File Context Construction (PAR-2),
  (iii)~Graph-Based \& Structural Representation (PAR-3),
  (iv)~Execution \& Dynamic Representation (PAR-4),
  (v)~Memory-Augmented Context (PAR-5),
  (vi)~Compression \& Summarization (PAR-6), and
  (vii)~Agentic \& Iterative Context Exploration (PAR-7).
  Each paradigm is characterized by its context-extraction
  mechanism, the structural properties of the repository it
  captures, its computational footprint, and its suitability
  for specific SE tasks.

  \item \textbf{A Task-Aware Mapping.}
  We systematically map each paradigm to the seven SE objectives
  covered in our corpus: code completion (O1), code generation
  from issues or NL specifications (O2), code search and feature
  localization (O3), bug fixing and issue resolution (O4),
  refactoring and code translation (O5), multi-file test
  generation (O6), and code review and static analysis (O7).
  This mapping exposes which paradigms dominate which tasks and
  where paradigm combinations yield the strongest results.

  \item \textbf{A Comparative Evaluation Framework.}
  We analyse the performance of primary studies across standardized
  benchmarks---including SWE-bench \cite{jimenez2024swebench},
  CrossCodeEval \cite{ding2023crosscodeeval},
  RepoBench \cite{liu2024repobench},
  DevEval \cite{li2024deveval},
  and FEA-Bench \cite{li2025feabench}---and
  derive empirically grounded design guidelines for selecting or
  combining repository representation strategies.

  \item \textbf{A Research Agenda.}
  Based on our analysis, we identify the most pressing open
  challenges: scalability to million-line repositories
  \cite{shi2025longcodezip,wang2026swepruner},
  cross-paradigm synergies
  \cite{phan2025repohyper,tao2025cgm,luo2026rpgencoder},
  multilingual and polyglot repository support
  \cite{ding2023crosscodeeval,liu2025m2rceval,zan2025multiswebench},
  and the need for reproducible, living benchmarks
  \cite{zhang2025sweblive,vergopoulos2025autobenchmark}.

\end{enumerate}

%% ----------------------------------------------------------
%% 1.6  Why This Taxonomy Matters Now
%% ----------------------------------------------------------
The urgency of this taxonomic effort is underscored by the
explosive pace of the field.
The SWE-bench leaderboard has been resolved above 50\% by recent
agentic systems
\cite{yang2024sweagent,zhang2024autocodeRover,ma2025lingmaagent},
yet the representation strategies underlying these successes are
rarely compared on equal footing.
Concurrently, the community is grappling with a reproducibility
crisis: many approaches are evaluated on custom benchmarks,
with proprietary models, or without releasing code artefacts
\cite{yang2025empiricalrag,gu2025whatretrieve}.
A rigorous, evidence-based taxonomy directly addresses both
problems by providing a common vocabulary and a structured
framework for principled comparison.
