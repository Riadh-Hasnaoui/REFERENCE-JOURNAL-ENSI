\section{Introduction}
\label{sec:introduction}

Modern software development increasingly relies on Large Language Models (LLMs)
to automate repository-level engineering tasks—ranging from cross-file code
completion and automated bug fixing to test generation and refactoring.  A
central, yet underexplored, question underpins all of these tasks: \emph{how
should an LLM-based system represent an entire code repository?}

A repository is not a single document; it is a heterogeneous artefact
comprising hundreds of interrelated files, build scripts, test suites, and
documentation.  Feeding the whole repository into an LLM context window is
neither scalable nor effective.  Practitioners therefore employ a spectrum of
\emph{representation strategies}—from dense vector embeddings and RAG-based
retrieval to code property graphs, execution traces, adaptive memory
mechanisms, and autonomous agentic exploration.

\subsection*{Research Questions}

\noindent\textbf{RQ1.} What paradigms of repository representation have been
proposed in the literature (2020–2025), and how can they be taxonomised?

\noindent\textbf{RQ2.} How do these paradigms map onto the principal
software-engineering objectives (code completion, bug fixing, refactoring,
test generation, code search)?

\noindent\textbf{RQ3.} What are the key trade-offs (precision, token budget,
latency, freshness, scalability) that guide the selection of a representation
paradigm in practice?

\subsection*{Contributions}

\begin{itemize}
  \item A seven-class taxonomy of repository representation paradigms
        (PAR-1 to PAR-7) grounded in 163~primary studies.
  \item A $7 \times 5$ bidirectional mapping matrix linking paradigms to
        SE objectives.
  \item A multi-dimensional trade-off framework for principled paradigm
        selection.
  \item Five research-gap hypotheses and a forward-looking research agenda.
  \item An online replication package (Zenodo) containing the complete
        snowballing log, data-extraction forms, and synthesis spreadsheets.
\end{itemize}
