\section{Introduction}
\label{sec:introduction}

The emergence of Large Language Models~(LLMs) has triggered a paradigm shift in
automated software engineering~(SE). Systems trained on massive corpora of source
code—from early pre-trained models such as CodeBERT~\cite{Feng2020CodeBERT} and
GraphCodeBERT~\cite{Guo2021GraphCodeBERT} to the unified cross-modal representation
of UniXcoder~\cite{Guo2022UniXcoder} and the long-range context model
LongCoder~\cite{Guo2023LongCoder}—have established that LLMs can perform
non-trivial SE tasks, from code completion and summarization to bug
fixing and test generation.
Recent surveys confirm the breadth of this transformation: Hou et
al.~\cite{Hou2024LLMsForSE} map the use of LLMs across all major SE activities,
Husein et al.~\cite{Husein2025LLMCodeCompletion} survey LLMs specifically for code
completion, and Jiang et al.~\cite{Jiang2026SurveyCodeGen} and Zhang et
al.~\cite{Zhang2026SurveyLLMsSE} offer comprehensive perspectives on code generation.

\subsection*{The Repository-Level Challenge}

Despite these advances, a fundamental mismatch remains between the granularity at
which LLMs operate and the granularity at which software is developed.
Industrial software lives in \emph{code repositories}: layered collections of thousands
of interdependent files, in-house libraries, build configurations, test suites, and
project histories.
A function-level LLM prompt captures at most a few hundred tokens of local context,
yet solving a real-world GitHub issue or implementing a repository-spanning feature
requires understanding module dependencies, global API contracts, and cross-file
dataflow~\cite{Bairi2024CodePlan,Jimenez2024SWEBench,Zhang2023RepoCoder}.
This is the \emph{repository-level challenge}: how to extract, structure, and deliver
repository-scale context to an LLM in a form it can effectively consume.

Evidence of the challenge is abundant. SWE-bench~\cite{Jimenez2024SWEBench} shows
that resolving real-world GitHub issues requires navigating repositories with hundreds
of files; RepoBench~\cite{Liu2024RepoBench} demonstrates that cross-file context
is essential for completion accuracy; CrossCodeEval~\cite{Ding2023CrossCodeEval}
benchmarks multilingual cross-file completion across diverse repositories; and
DevEval~\cite{Li2024DevEval} reveals that function-level LLMs fail on real-world
repository-aligned tasks. More recent benchmarks—FEA-Bench~\cite{Li2025FEABench},
REPOCOD~\cite{Liang2025REPOCOD}, DependEval~\cite{Du2025DependEval}, and
Multi-SWE-bench~\cite{Zan2025MultiSWEBench}—further expose the gap between
function-level capability and repository-level demand.

\subsection*{A Proliferation of Paradigms, Without a Unifying Taxonomy}

The research community has responded to this challenge with extraordinary energy,
producing hundreds of approaches over the past five years.
These approaches vary radically in their technical choices:

\begin{itemize}
\item \textbf{PAR-1 — Dense Embedding and Prompt Construction.}
  Works such as the Repository-Level Prompt Generator~\cite{Shrivastava2023RepPrompt},
  the cross-file alignment of Li et al.~\cite{Li2025AlignLLMs}, and the
  hierarchical context pruning of Zhang et al.~\cite{Zhang2025HierCtxPruning} build
  dense vector representations or structured prompts that encode repository context for
  LLM consumption.

\item \textbf{PAR-2 — Retrieval-Augmented Generation~(RAG).}
  Pioneered by ReACC~\cite{Lu2022ReACC} and RepoCoder~\cite{Zhang2023RepoCoder},
  RAG-based approaches dynamically retrieve relevant cross-file snippets to augment the
  LLM prompt. Subsequent work addresses retrieval precision~\cite{ZhangS2025CodeRAG},
  selective retrieval~\cite{Wu2024Repoformer}, hybrid strategies~\cite{Li2025HyRACC},
  multi-retrieval augmented generation~\cite{Tan2025PromptRAG},
  and industry-scale deployment~\cite{Yang2025EmpiricalRAG,Wang2025RAGFineTuning}.
  The breadth of this paradigm is further illustrated by CoCoMIC~\cite{Ding2024CoCoMIC},
  FT2Ra~\cite{Guo2024FT2Ra},
  CATCODER~\cite{Pan2025CATCODER}, and
  AlignCoder~\cite{Jiang2025AlignCoder},
  among many others~\cite{Bi2024IterativeRefinement,Chen2024CodeSearch,
  Deng2025InternalAPI,Gao2024PreferenceRAG,Hai2025Contexts,
  Hostnik2025RAGCompletion,Liao2024A3CodGen,Shen2025AdaptiveSeg}.

\item \textbf{PAR-3 — Graph-Based and Structural Representation.}
  This paradigm encodes the repository as a graph—Abstract Syntax Trees, data-flow
  graphs, dependency graphs, or knowledge graphs—capturing relational properties
  invisible to flat text models. Key contributions include
  GraphCoder~\cite{Liu2024GraphCoder},
  CodexGraph~\cite{Liu2025CodexGraph},
  the dataflow-guided retrieval of Cheng et al.~\cite{Cheng2024DataflowRAG},
  RepoGraph~\cite{Ouyang2025RepoGraph},
  GRACE~\cite{Wang2025GRACE},
  LocAgent~\cite{Chen2025LocAgent}, and
  GRACG~\cite{Fedorov2025GRACG}.
  Knowledge-graph variants include AskGraph~\cite{Yang2025AskGraph},
  the knowledge-enhanced bug localization of Li et al.~\cite{Li2025BugLocalization},
  and the CGM model~\cite{Tao2025CGM}.

\item \textbf{PAR-4 — Execution-Based and Dynamic Representation.}
  These approaches ground repository context in program behavior: execution traces,
  test outcomes, reinforcement signals, or runtime feedback.
  IRCoCo~\cite{Li2024IRCoCo} uses immediate rewards from reinforcement learning;
  Rete~\cite{Parasaram2023Rete} learns namespace representations for program repair;
  RLCoder~\cite{Wang2025RLCoder} trains completion models with RL;
  RAP-Gen~\cite{Wang2023RAPGen} retrieves and applies repair patches with compiler
  feedback; and SWE-Gym~\cite{Pan2025SWEGym} provides a gymnasium for training
  and verifying SE agents on execution outcomes.

\item \textbf{PAR-5 — Memory-Augmented Context.}
  Long-horizon SE tasks require persistent memory across agent steps.
  LingmaAgent~\cite{Ma2025LingmaAgent} manages a comprehensive memory store for
  issue resolution; CodeMEM~\cite{Wang2026CodeMEM} maintains an AST-guided adaptive
  memory for iterative code generation; Prometheus~\cite{Pan2026Prometheus}
  enables long-horizon codebase navigation; and SWE-Exp~\cite{Chen2025SWEExp}
  leverages past experience to drive issue resolution.

\item \textbf{PAR-6 — Compression and Summarization.}
  When repositories exceed LLM context limits, hierarchical summarization and compression
  become essential. CodeS~\cite{Zan2025CodeS} generates multi-layer sketches;
  LongCodeZip~\cite{Shi2025LongCodeZip} compresses long code contexts;
  SWE-Pruner~\cite{Wang2026SWEPruner} prunes context adaptively for coding agents;
  and hierarchical repository-level summarization~\cite{Dhulshette2025HierSumm,
  Makharev2025CodeSumm} enables business-scale code analytics using local LLMs.

\item \textbf{PAR-7 — Agentic and Iterative Context Exploration.}
  The most recent paradigm equips LLM agents with tools to actively navigate the
  repository, issuing file reads, search queries, test executions, and code edits in
  a feedback loop. Landmark systems include
  SWE-agent~\cite{Yang2024SWEAgent},
  MetaGPT~\cite{Hong2023MetaGPT},
  CodePlan~\cite{Bairi2024CodePlan},
  AutoCodeRover~\cite{Zhang2024AutoCodeRover},
  OpenHands~\cite{Wang2025OpenHands},
  CodeAgent~\cite{Zhang2024CodeAgent}, and
  RepairAgent~\cite{Bouzenia2025RepairAgent}.
  Agent-based approaches also address fault localization~\cite{Qin2025AgentFL,
  Chen2025LocAgent}, test generation~\cite{Altmayer2025CoverUp,Chen2024ChatUniTest,
  Go2025LSPRAG,Zhang2025TestGen},
  code translation~\cite{Ibrahimzada2025AlphaTrans,Zhang2025ScalableTrans,
  Feng2026CRust},
  and issue resolution at scale~\cite{Xia2025DemystifyingLLM,Ma2025SWEGPT,
  Wei2025SWERL,Li2025SWEDebate}.
\end{itemize}

Despite this remarkable proliferation, the community lacks a unified, principled framework
for classifying and comparing these approaches. Existing reviews either focus on specific
sub-problems—RAG for code generation~\cite{Tao2026RAGSurvey}, code completion
surveyed narrowly~\cite{Husein2025LLMCodeCompletion}—or cover LLMs for SE at a
level of abstraction that obscures representational choices~\cite{Hou2024LLMsForSE,
Jiang2026SurveyCodeGen,Zhang2026SurveyLLMsSE}. No prior study has proposed a
\emph{taxonomy} that jointly maps repository representation mechanisms to downstream
SE tasks, applies a PRISMA-compliant SLR methodology, and delivers a comparative
evaluation of benchmarks and metrics.

\subsection*{Contributions}

This paper fills that gap. We present \textbf{the first systematic literature review and
taxonomy of code repository representation approaches for LLM-based software
engineering}, grounded exclusively in the 168 primary studies assembled in our corpus.
Our specific contributions are as follows:

\begin{enumerate}

\item \textbf{A seven-dimensional taxonomy~(PAR-1 through PAR-7).}
  We classify repository representation approaches along two orthogonal dimensions:
  \emph{representational mechanism} (dense embedding, RAG, graph-based, execution-based,
  memory-augmented, compression/summarization, agentic) and \emph{downstream SE objective}
  (code completion, code generation, code search, bug fixing/issue resolution,
  refactoring/translation, test generation, code review/analysis).

\item \textbf{A PRISMA-compliant Systematic Literature Review.}
  Following the guidelines of Kitchenham and Charters~\cite{Kitchenham2007SLR},
  the PRISMA~2020 framework~\cite{Page2021PRISMA}, and the snowballing methodology
  of Wohlin~\cite{Wohlin2014Snowballing}, we designed a reproducible search protocol
  covering eight digital libraries, applied three inclusion criteria~(IC1–IC3) and six
  exclusion criteria~(EC1–EC6), and conducted forward/backward snowballing to ensure
  completeness.

\item \textbf{A comparative evaluation infrastructure analysis.}
  We systematically survey the benchmarks used to evaluate repository-level approaches,
  covering SWE-bench~\cite{Jimenez2024SWEBench},
  RepoBench~\cite{Liu2024RepoBench},
  CrossCodeEval~\cite{Ding2023CrossCodeEval},
  DevEval~\cite{Li2024DevEval},
  FEA-Bench~\cite{Li2025FEABench},
  M2RC-EVAL~\cite{Liu2025M2RCEval},
  DependEval~\cite{Du2025DependEval},
  and 17 further benchmarks~\cite{Cai2026SWEQAPro,Guo2025OmniGIRL,
  Liang2025REPOCOD,Liu2025ProjectEval,May2025FreshBrew,Miao2026RecodeH,
  Ou2025RustRepoTrans,Pavel2025SWEMERA,Vergopoulos2025AutoBench,
  Wang2026RepoTransBench,Xiang2026RustIssue,Xue2025ClassEvalT,
  Zan2025MultiSWEBench,Zhang2025DIBench,Zhang2025SWEBenchLive,
  Zheng2025HumanEvo,Zhou2026FeatureBench}.
  We analyze their scope, language coverage, SE task alignment, and reproducibility.

\item \textbf{A research agenda.}
  We identify open challenges, including the absence of standardized cross-paradigm
  evaluation, the scalability–precision trade-off in graph-based representations,
  context-window bottlenecks for million-line repositories, and the need for
  security- and privacy-aware repository representation.

\end{enumerate}
