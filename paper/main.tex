%%% Abstract ──────────────────────────────────────────────────────────────────
\begin{abstract}
Modern software engineering increasingly delegates repository-level tasks to
Large Language Model (LLM)-based agents, yet a fundamental architectural
question has gone unanswered: \emph{how} does an LLM-based system represent an
entire code repository within a finite context window?
We term this the \emph{Repository Representation Problem} (RRP) and present
the first Systematic Literature Review dedicated to it.

Our methodology integrates five complementary pillars: Kitchenham's SLR
guidelines, Wohlin's forward/backward snowballing, PRISMA~2020 reporting
standards, Cruzes and Dyb{\aa}'s thematic synthesis, and the ACM SIGSOFT
Empirical Standards.
Applying a four-stage screening protocol to 1,847 candidate studies, we
retained 159 primary studies spanning 2020--2026.

The central contribution is a \textbf{seven-paradigm taxonomy} (PAR-1 through
PAR-7): dense code embeddings, retrieval-augmented context construction,
graph-based structural representations, execution and dynamic
representations, memory-augmented context, compression and summarization, and
agentic iterative exploration.
Each paradigm is systematically characterised across ten analytical dimensions
and projected onto a 7$\times$7 paradigm--SE-objective mapping matrix covering
code completion, code generation, program repair, fault localisation, code
search, code translation, and test generation.

We further report that the static-repository assumption embedded in PAR-1,
PAR-3, and PAR-6 introduces a \textbf{10--61\% evaluation bias}, as
demonstrated empirically by the HumanEvo benchmark, and identify five
structural research gaps: temporal freshness, token-budget-aware hybridisation,
multilingual repository support, evaluation standardisation, and privacy-aware
local representation.

This SLR provides the first comprehensive \emph{input-side} complement to
existing \emph{output-side} surveys (Hou, Husein, Jiang, Tao, Zhang), and
establishes repository representation as a first-class architectural problem
in LLM-based software engineering.
\end{abstract}
